The Browser toolbar now selects an account profile and creates isolated profiles. Login, MFA and reauthentication remain manual in the browser or its login popup. A workflow detects visible login/challenge/expiry signals, account-marker changes, unexpected navigation and login windows, then pauses. It never fills credential/MFA fields. **Check account** reports whether a recognizable signed-in identity is visible; there is no generic page-element picker. Explicit current-account labels must contain an actual identifier. Ordinary controls, avatar placeholders and a static Account menu button cannot be selected as identity evidence, even through the existing semantic account-target API. Conflicting identities remain unbound. Capture stays disabled until an identity is bound. DOM markers are evidence from an untrusted website, not proof of a provider's account identity. Real websites need validated markers/adapters.

The YouTube-specific heuristic reads only a visible active-account header with a visible channel handle on `youtube.com`, `www.youtube.com` or `m.youtube.com`. It never uses the creator's channel link, menu-button label, email, hidden account headers, cookies or website JavaScript variables. Open the website's menu manually before **Check account** when needed. Missing or subsequently hidden identity fails closed; this heuristic does not establish unattended YouTube support. Controlled DOM tests cover the shapes above; live YouTube behavior and media acquisition remain unverified. Browser and Reels fixtures verify the replacement status/button UI and login-preserving cleanup.

The trusted preload exposes `startBrowserWorkflow({profileId, accountTarget?})`, `browserTool(...)`, `browserWorkflowState()`, `cancelBrowserWorkflow({workflowId})`, `resumeBrowserWorkflow({workflowId, profileId, accountTarget?, restorePage?})` and `clearBrowserWorkflowMedia()`. `accountTarget`, when supplied, is an exact `{role, name}` pair. Only one workflow and one operation can control the current page. Profile selection and page/document revisions are checked throughout operations.

| Tool action | Contract |
| --- | --- |
| `read` / `discover` | Return bounded rendered prose, semantic roles/names and fresh element references. Content is explicitly untrusted. No HTML/scripts, hidden fields, form values, headers, cookies or signed addresses are returned. Discovery uses an exact semantic target. Rediscovery invalidates earlier element references. |
| `navigate` | Public HTTPS within the workflow origin; bounded readiness wait and resulting page state. Production never permits the test fixture's HTTP/loopback exception. |
| `click` / `fill` | Require current `pageRef` and `elementRef`. Reject detached, changed, ambiguous, disabled, readonly, credential and stale-document targets. Account/challenge checks precede the action inside the isolated world. Clicks are never retried. Fill verifies the immediate field outcome without returning its value. Click returns resulting page state; workflow callers must check their business postcondition rather than interpret dispatch as business success. |
| `scroll` / `wait` | Bounded scrolling and explicit document-ready or unique semantic-element readiness. No fixed-delay success assumptions. |
| `capture` | Requires a unique video reference and bound account marker. Acquires its current direct address in the selected Chromium session, then captions and complete local audio. Only one same-source signed-address refresh is attempted. Complete transfer/decode verification precedes opaque references. Reels passes `requireCaption:true`, requiring a caption element belonging to the selected video's article, including explicitly empty captions. Generic page metadata alone cannot establish complete reel captions. |
| `reels` | Read-only discovery of up to 100 visible same-origin stable `/reel/<id>/` links; canonical addresses omit query/fragment secrets. Requires a current page reference. A virtualized conversation must be scrolled and selected again for older links. |

Normal operations default to 10 seconds and allow 100 ms–30 seconds. Capture defaults to 120 seconds and allows at most 180 seconds; decoder work is bounded to 100 seconds. Timeouts fail the operation and close the controlled page. Cancellation aborts network requests, signals queued/active decoding, waits for worker exit, and removes partial outputs; cancellation during an operation closes the page to prevent a queued late action. Persistent login data survives. Pauses require explicit human review/reauthentication. Restart recovery creates fresh workflow/document/element references and never replays a click. Resuming requires the checkpoint's profile and original last-verified page.

October 8 recovery correction: **Start browser workflow** starts fresh after cancelled/completed/failed work and never implicitly selects a historical checkpoint. A paused workflow offers **Open saved page and resume** and **Start new on this page**. Explicit recovery can restore a safe unsigned saved origin/path in the selected profile, reuse its uniquely matching tab, and wait for navigation (15 seconds) and document readiness (10 seconds). Destination validation remains bounded and applies the existing public-address policy. The optional trailing slash on the same stable `/reel/<id>` is accepted; different reel IDs, origins and generic paths remain distinct. Older checkpoints without a reconstructible address and query/fragment-dependent or redacted addresses require manual review or a fresh workflow. New checkpoints retain only a hashed account marker; resumed page/account checks reject redirects, challenges and account mismatches before further actions. Failed recovery retains the original identity for retry; cancellation keeps the recovery lease until it exits. No saved click or media capture is replayed.

Media acquisition currently supports complete direct MP4/WebM (or a supported complete container delivered as octet-stream), at most 256 MiB and ten minutes, with a known full response length. It captures available page description and up to 16 WebVTT tracks of at most 1 MiB each. Missing audio/captions are explicitly reported as absent. Blob/MSE, HLS/DASH, DRM, separate page audio, unknown-length/partial responses, multiple audio tracks, unsupported caption formats and missing account identity are unsupported acquisition cases. Separate audio elements are rejected instead of presenting a silent container as complete reel audio. It does not claim to recover provider metadata/captions or Web Audio orchestration that are not exposed by this page contract.

Results contain `browser-media:<workflow-id>:video|audio|captions`, safe source origin/path/identity, profile ID, SHA-256 and completeness. `backend/services/browser_media.py::resolve_reference` resolves only verified references. `/browser-media/...` routes require both the normal launch credential and the existing native-only capability; model-supplied paths, URLs and credentials are rejected. These routes never fetch remotely. Remote transfer uses Chromium's selected session without reading cookie values. Electron's documented session/credential and manual-redirect behavior informed the implementation: [ClientRequest](https://www.electronjs.org/docs/latest/api/client-request), [persistent sessions](https://www.electronjs.org/docs/latest/api/session).

Profile registry and workflow checkpoints live beside Chromium profiles under desktop userData. Checkpoints contain IDs/status, safe source identity and verified result metadata, with no DOM, field entries, raw/signed URLs or session secrets. Workflow media has its own `browser-workflows/media` subtree, independent of checkpoints and saved analyses. Its aggregate bound is 512 MiB, with conservative space reservations for a maximal capture, captions and extracted audio. Completed media expires on startup after 24 hours. Incomplete/orphaned media is removed on startup; completed/failure/cancellation cleanup never clears Chromium cookies/site storage, ordinary downloads or saved application results. Live checkpoint history is bounded to 200 records; released terminal records move into a separate durable `archive` as more workflows start. Interrupted checkpoints remain available for manual review. The analyzer releases captured media after each saved result.

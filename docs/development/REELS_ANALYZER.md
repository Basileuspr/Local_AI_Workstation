# Reels Analyzer — implementation and verification

October 7, 2026. Implemented in the actual dirty working checkout after the [browser foundation audit](BROWSER_FOUNDATION.md). Existing and concurrent edits to unrelated features were preserved. This is a functioning desktop subsystem with controlled fixture acceptance and actual local model validation. Real Instagram acquisition remains a separate, unverified requirement; login alone is never treated as acquisition success.

## What existed and what changed

| Area | Inspected implementation | Scoped addition |

Integration checks bind processing to its selected profile/tab/document and preserve unrelated tabs. |

## Using the pane

Open **Reels Analyzer** in the workspace navigation. In its account browser, select or create the account's isolated profile and log in normally, including MFA. Open the conversation containing shared reels. **Check account** reports whether a signed-in identity is recognized. If necessary, open the website's account menu so your name or handle is visible and check again. Unsupported or ambiguous pages remain unidentified; there is no dropdown of playback/navigation controls and no role/name entry. Identifying a rendered account marker is not proof supplied by the provider. The check is discarded when the selected profile, tab or document changes; discovery and acquisition independently recheck identity.

Choose an installed local vision model, local summary model and installed Whisper model. **Use this conversation** discovers at most 100 visible stable reel addresses. Scroll and select the conversation again to include older links from a virtualized message history. **Analyze discovered reels** starts the sequence. It first checks local model availability; each reel then must pass full media and caption acquisition before any analysis.

**Pause after this reel** stops after save, cleanup and return to the conversation. **Cancel** signals active acquisition/inference and retains ownership until its worker stops. **Resume remaining reels** opens the saved conversation when a reel or another page is left open, then verifies the original account before processing pending items. Select the original account profile first; recovery does not switch profiles. A uniquely matching source tab is reused, or the current tab returns to the saved address. An active Browser workflow must be cancelled first; a paused Browser lease can be released during explicit recovery. Navigation and readiness are bounded, recovery owns the page, and failed recovery can be retried. It never duplicates a saved identity. **Open source conversation** also reveals the account browser for manual review/login. **Clear cache** removes this subsystem's remaining temporary evidence and preserves account sessions and saved summaries.

Saved output is two or three short sentences, a clearly extracted clickable repository address when available, and the original reel link. Unclear or conflicting addresses display exactly **Repository link not identified.** Unsupported/incomplete acquisition or analysis is flagged separately and never saved as a complete analysis. Repository links open only upon an explicit click.

## Workflow and recovery

`electron/reelsAnalyzer.js` owns one sequence. For each pending item it reads the original source/account, navigates to the canonical stable reel URL, waits for a unique semantic video target and checkpoints its workflow ID before acquisition. It requests verified complete video, complete audio or verified audio absence, and complete caption data or verified empty captions. Acquisition returns opaque local references; signed media addresses remain inside Chromium.

The desktop calls the native-only `/reels` backend using the existing launch credential and native capability. The backend validates the captured reel against the checkpoint, claims its stable identity, obtains the existing `local-video` CPU lane, and later obtains the shared GPU queue for vision/summary work. Only one still/image request is processed at a time. Separate summary models run after unloading the vision model. Whisper uses the existing CPU implementation, avoiding concurrent GPU pressure on this workstation's 8 GiB RTX 3070. Cancellation checks cover queued work, decoding, transcription segments and streamed model responses.

The backend commits the brief result and completed-item checkpoint in one SQLite transaction, then deletes video/audio/transcript/frames/evidence. Electron releases browser capture metadata and renews account/document checks before controlled navigation back to the conversation. Only then can the next item open. Selected profile, tab, URL and document revision are checked while local inference is pending. A separate read-only semantic workflow checks visible account/login/challenge markers during inference without sending page text to the model or saving it. Changes signal cancellation; account/challenge checks are renewed before leaving the reel. Another browser-tool workflow cannot take over through desktop IPC while Reels owns the sequence. Manual navigation remains possible and causes a pause. No automatic replay of clicks or credential entry occurs.

If the backend is still stopping or unavailable, the controller keeps its lease and disables new sequences/cache deletion until **Cancel** confirms worker exit. On restart, incomplete captures are removed, acquiring/analyzing checkpoints become interrupted and saved identities remain deduplicated. The SQLite unique key covers the same site/reel ID even when rediscovered through another account. Browser checkpoint metadata is separate from queue history; released terminal browser records archive after the 200-record live history limit.

## Accuracy and bounds

Acquisition checks full response bytes, SHA-256, complete video/audio demux/decoding, timestamps, duration and stream endings. Analysis verifies the media hash again. Speech retains local segment timestamps. Every decoded video frame is examined for scene/text changes; retained stills cover the entire clip at regular intervals, transition neighbors and brief text changes. Unclear text triggers additional nearby sampling and overlapping native-resolution crops. The bounded accuracy pass fails explicitly if it cannot fit the limits, rather than silently thinning evidence and claiming complete analysis.

Limits are ten minutes and 256 MiB per acquired video, 512 MiB per temporary evidence workspace, 480 stills including refinements, 16 unclear-text regions, bounded decoder/refinement time and a 40-minute local vision/summary stage. Model inputs use the existing model context metadata, bounded evidence groups and literal source quotes. Model responses have structured schemas, bounded output and a single retry for an invalid summary draft. See Ollama's [structured-output contract](https://docs.ollama.com/capabilities/structured-outputs).

Important names must be spelled in cited evidence. Quotes must match captured evidence literally. A separate local verification pass checks every summary claim and its attribution. Creator capabilities are reported as creator claims; no outside facts are independently established or searched. Captions, transcripts and printed instructions remain untrusted source data.

Repository extraction accepts full `github.com`, `gitlab.com` or `codeberg.org` owner/repository addresses. Addresses from images require agreement between the full frame and an original-resolution crop. A caption's explicit complete address is also usable. ASR guesses, shortened links, unclear characters, ellipses and invented/completed addresses are rejected. Multiple distinct supported repository addresses remain unidentified. This conservative contract can miss an address; it must not fill in missing characters. Neither discovery nor analysis visits extracted repositories.

## Storage and security

Chromium sessions remain in their isolated persistent partitions under Electron userData. The browser workflow media subtree is `userData/browser-workflows/media/<generated-workflow-id>`. Reels adds only disposable `analysis` files beneath that generated child. All temporary video, extracted audio, timestamps/transcription, stills, crops and intermediate evidence stay there. None are imported into the public web cache, media gallery or knowledge store.

Saved batches and brief summaries live at `settings.data_dir/reels/results.sqlite3`; batches hold profile ID, canonical unsigned source/reel URLs, hashed rendered-account marker, model names and statuses. They do not store rendered conversation text, transcripts, frames, cookies, passwords, authorization headers or signed addresses. URLs with embedded credentials and common credential/header patterns are redacted before model input. The browser transfer uses its selected session without exporting cookie values. Temporary media deletion is independent of browser cache and cookies/site storage.

Trusted main-frame IPC checks, native-only backend operations, launch authentication, remote sandboxing/context isolation/Node-off preferences, production TLS validation and public/private destination restrictions remain in effect. Transfers validate each redirect; popups retain their profile's policy. Model content cannot choose a URL fetch, filename, script, debugger or cookie operation. The ordinary browser download/inspection approval controls remain intact.

## Remaining blockers and unverified behavior

**Instagram compatibility is not demonstrated.** No actual conversation URL, logged-in account session, real MFA/expiry/reauthentication, provider account marker, provider reel caption or complete Instagram video/audio retrieval was exercised. A real session must first demonstrate acquisition; a provider adapter is likely necessary for captions and streamed playback. The next real-account check requires a source conversation URL and manual login in its selected workstation profile.

The current adapter supports stable visible `/reel/<id>/` links and complete direct HTTP(S) containers in the selected session. Production requires public HTTPS. Query/fragment-defined conversation sources and opaque source paths require a site adapter; canonical checkpoints must preserve the actual selected conversation identity. Blob/MSE playback, HLS/DASH, DRM, separate page audio, partial/unknown-length responses and provider captions that cannot be bound to the selected reel are explicitly unsupported. A detected separate audio element rejects acquisition; a silent video container cannot stand in for audio played elsewhere. Provider-specific Web Audio/stream orchestration still requires an adapter and real-session validation. For Reels, a generic `og:description` alone is insufficient; the selected article must expose its caption element, including an explicit empty caption. DOM/account markers require validation against the real provider, and virtualized conversation history is not crawled unattended.

The ordinary build encountered two existing environment issues: intermittent Windows `WinError 5` while replacing the default application-review HTML, and Vite's absolute emitted HTML path error when building through the `C:` junction. Production compilation succeeded from the resolved `E:\LocalAI\Local_AI_Workstation` checkout using the existing `LAW_BUILD_REVIEW_DIR=tmp/reels-production-review` setting. This directs review artifacts to a separate folder while retaining source capture and the compiler's source-identity verification. It does not change or disable the build system. The resulting `dist` contains Reels Analyzer; no packaged installer or running installed-app restart was tested. The default-path environment issues remain outside this feature's changes.
